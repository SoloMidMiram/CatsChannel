## #5 integration gates retained

authorized_reply_target is a trusted internal assertion, not an authentication
credential by itself. ReplyTarget checks canonical IDs; the submission service
checks parent/thread membership. A valid same-thread pair does not prove possession
of an authorized opaque token. #5 must obtain/revalidate the context through the
actor-aware resolver and must not deserialize public IDs or flags into authority.
The current PR exposes no new intake handler, so this is a documented integration
requirement rather than a reproduced external vulnerability in PR #27.

The submission record stores placement thread, not the exact selected parent or
requested mode. Once created, PostIntent stores those immutable details. #5 must
durably preserve/verify original mode and parent across the submission-before-intent
failure boundary; private projection lookup alone cannot reconstruct them after
lost workflow context. The PR explicitly assigns this recovery to #5, so the
review does not misclassify that future feature as a missing #6 implementation.
